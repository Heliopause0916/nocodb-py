# NocoDB 列类别与值百科

## 概述

本文档是 NocoDB Python SDK 的列类型参考指南，旨在帮助用户理解和使用 NocoDB 中的各种列类型。无论您是数据管理员、开发者还是业务用户，都可以通过本文档了解不同列类型的特点、使用场景和注意事项。

**官方参考文档**：[NocoDB 字段类型文档](https://nocodb.com/docs/product-docs/fields)

## 数据类型说明

在 NocoDB Python SDK 中，每个列类型涉及三种数据类型表示：

1. **API 返回类型**：`get_record()` 等方法从 API 返回的原始数据类型
2. **API 接受类型**：`create_records()` 和 `update_records()` 方法接受的输入数据类型
3. **Python 推荐类型**：在 Python 代码中推荐的等效数据类型

**注意**：所有 API 接受类型都必须是 JSON 规范允许的类型（字符串、数值、布尔值、字典、数组、null）。

## 列类型分类

NocoDB 提供了丰富的列类型，可以满足各种数据管理需求。我们将列类型分为以下几个主要类别：

### 1. 基础数据类型
适用于存储基本的数据信息

### 2. 选择类型
提供预定义选项供用户选择

### 3. 验证类型
内置数据验证规则的特殊类型

### 4. 特殊功能类型
提供特定功能的列类型

### 5. 系统管理类型
由系统自动管理的列类型

## 基础列类型标识 (is_basic)

在 NocoDB Python SDK 中，我们引入了 `is_basic` 属性来标识基础列类型。基础列类型具有以下特征：

- **可写性**：用户可以独立修改这些列的值
- **结构简单**：数据无嵌套，结构简单
- **独立性**：不受其他列、表或值的影响
- **直接修改**：可以直接通过记录操作 API 修改

基础列类型是记录操作中最常用的类型，SDK 在处理这些类型时会进行优化。

## 基础数据类型

### 单行文本 (SingleLineText)
- **用途**：存储简短文本信息，如姓名、标题、标签等
- **特点**：长度无限制，适合存储简短内容
- **API 返回类型**：`string`
- **API 接受类型**：`string`
- **Python 推荐类型**：`str`
- **示例值**：`"张三"`, `"项目标题"`, `"标签名称"`

### 长文本 (LongText)
- **用途**：存储较长的文本内容，如描述、备注、文章等
- **特点**：支持富文本编辑，可包含格式和链接
- **API 返回类型**：`string`
- **API 接受类型**：`string`
- **Python 推荐类型**：`str`
- **示例值**：`"这是一个详细的描述..."`, `"项目说明文档"`

### 数字 (Number)
- **用途**：存储整数数值
- **特点**：支持大整数，可设置本地化显示格式
- **API 返回类型**：`integer`
- **API 接受类型**：`integer`
- **Python 推荐类型**：`int`
- **示例值**：`12345`, `-100`, `999999`

### 小数 (Decimal)
- **用途**：存储带小数点的数值
- **特点**：可控制小数位数精度
- **API 返回类型**：`string`（格式化数值）
- **API 接受类型**：`string` 或 `number`（TODO: 需要测试数值类型支持）
- **Python 推荐类型**：`float`
- **示例值**：`"3.14"`, `"0.50"`, `"100.00"`

### 日期 (Date)
- **用途**：存储日期信息
- **特点**：格式为 YYYY-MM-DD，支持日期选择器
- **API 返回类型**：`string`
- **API 接受类型**：`string`
- **Python 推荐类型**：`datetime.date`
- **示例值**：`"2023-12-24"`, `"2024-01-01"`

### 时间 (Time)
- **用途**：存储时间信息
- **特点**：支持12小时制和24小时制
- **API 返回类型**：`string`
- **API 接受类型**：`string`
- **Python 推荐类型**：`datetime.time`
- **示例值**：`"14:30:00"`, `"02:30 PM"`

### 日期时间 (DateTime)
- **用途**：存储完整的日期和时间信息
- **特点**：ISO 8601格式，包含时区信息
- **API 返回类型**：`string`
- **API 接受类型**：`string`
- **Python 推荐类型**：`datetime.datetime`
- **示例值**：`"2023-12-24T14:30:00Z"`

### 年份 (Year)
- **用途**：存储年份信息
- **特点**：只存储年份数值
- **API 返回类型**：`integer`
- **API 接受类型**：`integer`
- **Python 推荐类型**：`int`
- **示例值**：`2023`, `2024`

### 复选框 (Checkbox)
- **用途**：表示布尔值（是/否，真/假）
- **特点**：显示为复选框，值为0或1
- **API 返回类型**：`integer`（0或1）
- **API 接受类型**：`integer`（0或1）或 `boolean`
- **Python 推荐类型**：`bool`
- **示例值**：`1`（选中）, `0`（未选中）

## 选择类型

### 单选 (SingleSelect)
- **用途**：从预定义选项中选择一个值
- **特点**：下拉选择框，确保数据一致性
- **API 返回类型**：`string`（选项标题）
- **API 接受类型**：`string`（选项标题）
- **Python 推荐类型**：`str`
- **示例值**：`"选项A"`, `"高优先级"`, `"进行中"`

### 多选 (MultiSelect)
- **用途**：从预定义选项中选择多个值
- **特点**：支持选择多个选项，值以逗号分隔
- **API 返回类型**：`string`（逗号分隔的选项标题）
- **API 接受类型**：`string`（逗号分隔）或 `array`（TODO: 需要测试数组格式支持）
- **Python 推荐类型**：`List[str]`
- **示例值**：`"选项A,选项B"`, `"标签1,标签2,标签3"`

### 百分比 (Percent)

- **特点**：0-100范围，可显示为进度条
- **API 返回类型**：`integer` 或 `number`
- **API 接受类型**：`integer` 或 `number`
- **Python 推荐类型**：`float`
- **示例值**：`75`（表示75%）, `33.3`

### 时长 (Duration)
- **用途**：存储时间长度
- **特点**：支持小数精度
- **API 返回类型**：`string`（格式化时长值）
- **API 接受类型**：`string` 或 `number`（TODO: 需要测试数值类型支持）
- **Python 推荐类型**：`float`
- **示例值**：`"3600.00"`（表示3600秒）

### 评分 (Rating)
- **用途**：进行评分或评级
- **特点**：星形评分，可自定义最大分值
- **API 返回类型**：`integer`
- **API 接受类型**：`integer`
- **Python 推荐类型**：`int`

### 附件 (Attachment)
- **用途**：存储文件附件
- **特点**：支持多个文件，包含文件信息

- **API 接受类型**：`array` 或 `null`
- **Python 推荐类型**：`List[Dict]` 或 `None`
- **示例值**：文件对象数组或 `null`（无附件）

### JSON
- **用途**：存储结构化数据
- **特点**：支持任意JSON格式数据
- **API 返回类型**：`string`（JSON序列化字符串）

### 几何 (Geometry)
- **用途**：存储几何形状数据
- **特点**：WKT（Well-Known Text）格式
- **API 返回类型**：`string`
- **API 接受类型**：`string`
- **Python 推荐类型**：`str`
- **示例值**：`"POINT(30 10)"`, `"LINESTRING(30 10, 10 30, 40 40)"`

### 地理数据 (GeoData)
- **用途**：存储地理位置坐标
- **特点**：经纬度坐标，分号分隔
- **API 返回类型**：`string`
- **API 接受类型**：`string`
- **Python 推荐类型**：`str`
- **示例值**：`"31.8293774411;117.1143854933"`

## 自动生成类型

### 二维码 (QrCode)
- **用途**：基于关联列的值自动生成二维码
- **特点**：只读字段，值由系统自动生成
- **API 返回类型**：`string`
- **API 接受类型**：`string`（只读，忽略输入）
- **Python 推荐类型**：`str`
- **依赖**：需要关联其他列（如邮箱、URL等）

### 条形码 (Barcode)
- **用途**：基于关联列的值自动生成条形码
- **特点**：只读字段，值由系统自动生成
- **API 返回类型**：`string`
- **API 接受类型**：`string`（只读，忽略输入）
- **Python 推荐类型**：`str`
- **依赖**：需要关联其他列（如产品编号等）

### 公式 (Formula)
- **用途**：基于其他列的值进行计算
- **特点**：只读字段，自动计算结果
- **API 返回类型**：`string` 或 `number`（取决于公式类型）
- **API 接受类型**：`string` 或 `number`（只读，忽略输入）
- **Python 推荐类型**：`Any`（字符串、数值等）
- **示例**：`"单价 * 数量"`, `"平均值(销售额)"`

### 查找 (Lookup)
- **用途**：从关联表中查找相关数据
- **特点**：只读字段，自动填充关联数据
- **API 返回类型**：`array`
- **API 接受类型**：`array`（只读，忽略输入）
- **Python 推荐类型**：`List`
- **示例**：从客户表查找客户名称

### 汇总 (Rollup)
- **用途**：对关联记录进行汇总计算
- **特点**：只读字段，自动计算汇总值
- **API 返回类型**：`string` 或 `number`
- **API 接受类型**：`string` 或 `number`（只读，忽略输入）
- **Python 推荐类型**：`Any`（字符串、数值等）
- **示例**：`"总计(订单金额)"`, `"计数(订单数量)"`

### 按钮 (Button)
- **用途**：创建可点击的按钮
- **特点**：只读字段，配置按钮动作
- **API 返回类型**：`object`
- **API 接受类型**：`object`（只读，忽略输入）
- **Python 推荐类型**：`Dict`
- **功能**：URL跳转、自定义动作等

### 用户 (User)
- **用途**：关联系统用户
- **特点**：支持单用户或多用户模式
- **API 返回类型**：`array`（用户对象数组）
- **API 接受类型**：`array`（用户对象数组）
- **Python 推荐类型**：`List[Dict]`
- **示例**：创建者、负责人、协作者

## 系统管理类型

### 系统列（自动管理）

以下列由 NocoDB 系统自动管理，用户无法修改其值：

| 列名 | 说明 | 特点 | API 返回类型 | API 接受类型 | Python 推荐类型 |
|------|------|------|-------------|-------------|----------------|
| **Id** | 记录唯一标识 | 自增整数，每张表有且仅有一个 | `integer` | `integer`（只读） | `int` |
| **CreatedAt** | 创建时间 | 记录创建时自动设置 | `string` | `string`（只读） | `datetime.datetime` |
| **UpdatedAt** | 最后修改时间 | 记录更新时自动更新 | `string` | `string`（只读） | `datetime.datetime` |
| **nc_created_by** | 创建者 | 记录创建时自动设置用户ID | `string` | `string`（只读） | `str` |
| **nc_updated_by** | 最后修改者 | 记录更新时自动设置用户ID | `string` | `string`（只读） | `str` |
| **nc_order** | 排序字段 | 用于自定义排序逻辑 | `integer` | `integer`（只读） | `int` |

### 链接列（关系管理）

当您创建表间关系时，系统会自动生成链接列：

| 关系类型 | 说明 | 处理方式 | API 返回类型 | API 接受类型 | Python 推荐类型 |
|----------|------|----------|-------------|-------------|----------------|
| **一对一 (OneToOne)** | 两个记录之间的一对一关系 | 直接显示关联记录 | `object` | `object`（只读） | `Dict` |
| **多对一 (BelongsTo)** | 多个记录属于一个父记录 | 显示父记录信息 | `object` | `object`（只读） | `Dict` |
| **一对多 (HasMany)** | 一个记录有多个子记录 | 显示子记录数量 | `integer` | `integer`（只读） | `int` |
| **多对多 (ManyToMany)** | 多个记录与多个记录关联 | 显示关联记录数量 | `integer` | `integer`（只读） | `int` |

**注意**：链接列的值是只读的，需要通过专门的链接API来管理关联关系。

## 使用指南

### 创建记录时的注意事项

1. **系统列自动忽略**：创建记录时，系统列（Id、CreatedAt等）会被自动忽略，即使您提供了值也会被系统覆盖。

2. **只读字段处理**：自动生成类型（二维码、公式等）的值由系统计算，您提供的值会被忽略。

3. **必填字段**：确保所有标记为必填的字段都提供了有效值。

4. **数据类型匹配**：确保提供的数据类型与列定义的类型匹配。

### 更新记录时的注意事项

1. **系统列只读**：系统列的值无法修改，任何修改尝试都会被忽略。

2. **只读字段保护**：自动生成类型的字段无法直接修改。

3. **ID字段必需**：更新记录时必须包含记录的ID字段。

4. **部分更新支持**：可以只更新部分字段，未提供的字段保持原值。

### 数据验证规则

NocoDB 会自动验证数据的有效性：

1. **格式验证**：邮箱、URL、电话号码等类型会验证格式正确性。

2. **范围验证**：数字、百分比等类型会验证数值范围。

3. **选项验证**：选择类型会验证值是否在预定义选项中。

4. **必填验证**：标记为必填的字段必须提供值。

## 最佳实践

### 列类型选择建议

1. **文本数据**：根据长度选择单行文本或长文本
2. **数值数据**：根据精度需求选择数字或小数
3. **日期时间**：根据精度需求选择日期、时间或日期时间
4. **分类数据**：使用选择类型确保数据一致性
5. **关联数据**：使用链接类型建立表间关系

### 性能优化建议

1. **避免过度使用公式**：复杂的公式计算可能影响性能
2. **合理使用附件**：大文件附件会影响加载速度
3. **优化链接关系**：过多的关联关系可能影响查询性能

### 数据一致性建议

1. **使用选择类型**：确保分类数据的一致性
2. **设置验证规则**：防止无效数据输入
3. **利用只读字段**：使用自动生成类型减少人工错误

## 常见问题

### Q: 为什么我无法修改某些字段的值？
A: 系统列和自动生成类型的字段是只读的，由系统自动管理。您只能修改用户定义的可写字段。

### Q: 如何管理表间的关系？
A: 使用专门的链接API方法来添加或移除关联关系，而不是直接修改链接列的值。

### Q: 为什么我的邮箱/URL验证失败？
A: 请确保提供的值符合标准的邮箱或URL格式。NocoDB会进行严格的格式验证。

### Q: 如何处理多选字段的数据？
A: 多选字段支持字符串（逗号分隔）或数组格式。SDK会自动处理格式转换。

### Q: 附件字段支持哪些文件类型？
A: 附件字段支持各种文件类型，包括文档、图片、音频、视频等。
